🛰️一机四吃 · 用一台小鸡的四个 IPv6 做 TW/HK/SG/JP 分区落地

发表于2026-08-20|更新于2026-08-20|学习の世界
|总字数:2.8k|阅读时长:9分钟|浏览量:

本文只讨论自建代理的网络技术，机器和线路都是自己付费买的。请遵守当地法律法规，别拿去干坏事。

前言

昨天晚上十点多，师傅在群里丢过来一句：

用 mmw 给这个落地打针，建个 socks5。

我当场愣住 —— socks5 是什么？我研究一下。

一个半小时后，我的订阅里多了四个地区的节点，而它们背后其实是同一台香港小鸡。打开 ChatGPT 走新加坡，打开奈飞也走新加坡，想让哪个网站走日本、走台湾，改一行域名就行。

用师傅的话说，这叫「一机四吃」。

这篇把整个过程原样记下来。包括我中途卡住的那两次 —— 一次是三个 IP 只出来一个，一次是差点把原来的节点改坏。

一、先搞明白这事儿的原理

在动手之前，得先明白为什么一台机器能变出四个地区。

关键在 IPv6。

IPv4 地址早就枯竭了，一台小鸡能分到一个就不错了。但 IPv6 多到用不完 —— 一个 /64 段里的地址数量比整个 IPv4 空间还大好几万倍。所以有些商家可以直接给你分发不同地区的 IPv6，让你一台机器同时持有香港、台湾、新加坡、日本的出口地址。

我用的是 AetherCloud 的香港小鸡。它本身是香港 IP，另外还能通过官方脚本领到 TW / SG / JP 三个地区的 IPv6。

加上它自己原生的香港，一共四个出口：

🇭🇰 香港 —— 机器原生，默认就是它，不用额外配

🇹🇼 台湾 —— 中华电信家宽来的，动态的，会变

🇸🇬 新加坡 —— StarHub

🇯🇵 日本 —— 固定

然后整条链路是这样跑的：

为什么要中转？因为落地机直连体验不一定好，而旺角那台是优化过的线路机，国内连过去只有十几毫秒。师傅原话：「你有一个好的线路机，自己找落地拉就是了。」

中转负责「怎么稳稳地出去」，落地负责「从哪儿出去」，各司其职。

三、我卡住的第一次：三个 IP 只出来一个

脚本跑完，我美滋滋去查每个地址是哪个地区的，结果三个全显示新加坡。

没有日本，没有台湾。

我又跑了一遍交互模式，选 all，还是新加坡。反复几次都一样，人都麻了。

查地址归属我用的这个站：ippure.com，能看出 IP 的地区和「纯净度」。查的时候还被 Cloudflare 拦了一道人机验证，我截图发群里说「我不是人，我是机」，师傅估计笑死。

后来师傅甩过来一整段命令，说「整段复制进去」：

跑完再 ip -6 addr show，三个地区齐了。

这段在干嘛？我事后才琢磨明白：

  • DYNAMICV6_AUTO_TIMER=0 —— 关掉脚本自己的定时器，别跟手动操作打架
  • ip -6 neigh flush —— 把 IPv6 邻居缓存清掉，旧的对应关系不清就一直用错的
  • 后面那个循环 —— 逐个路由表找到网关，各 ping 一下把邻居关系激活

说白了就是：地址其实早就下发下来了，但邻居缓存是脏的，得踢一脚才认。

拿到地址之后，一定要在 SSH 里 ping 一下，确认真的通：

台湾那个是动态的。 师傅特意提醒了，它是中华电信家宽来的，会变。所以台湾这条先放着，别急着往规则里写死 —— 变了就得回来改。

四、在妙妙屋里建落地

地址到手，回到妙妙屋 X 面板。

4.1 建一个 SOCKS5 入站

落地机对中转机暴露的接口，用 SOCKS5 协议。在这台 Aether 服务器上新建一个 socks5 入站，设好用户名密码就行。

这里我得多说一句：SOCKS5 的用户名密码是明文传输的（RFC 1929 就这么定的）。它裸跑在公网上，中间任何一跳理论上都能抓到你的凭据。

我的用法是它只给自己的中转机拉，没往订阅里当直连节点发。你要是也这么玩，端口尽量别用常见的，密码给复杂点。

4.2 出站管理：三个出站，各绑一个 IPv6

面板里走 服务管理 → xray 配置 → 出站管理，加三个出站。

关键是这两个字段：

字段 填什么
sendThrough 该地区的 IPv6 地址（出站源 IP）
域名策略 UseIPv6v4

三个出站分别绑 TW / SG / JP 的地址：

（换成你自己领到的那三个）

香港不用单独加。 因为机器默认就是从香港的 v6 出去的，不配规则的流量自然走香港。

域名策略为什么选 UseIPv6v4？ 意思是「优先 v6，其次 v4」。因为有些网站压根不支持 IPv6，只走 v6 会直接打不开，得留个 v4 兜底。

4.3 路由管理：什么网站走哪个出口

再到 路由管理 → 添加自定义规则，一条规则三件事：

domain —— 你想让哪些网站走这个出口

入站标签 —— 选刚才建的那个 socks5

出站 —— 选对应地区的那个出站

域名格式师傅给了个现成的，直接抄：

格式规则很简单：

  • domain:xxx.com —— 整个域名及其子域名都算
  • 前面不加 domain: —— 就是精确匹配这一个域名
  • 多条之间用 , 分开

api64.ipify.org 那条是故意加的，等下验收要用。

想玩得更细就多加几条规则：日本网站走 JP、金融走 SG、其他走 HK。入站是同一个 socks5，出站分流了 —— 这就是「一机四吃」的核心。

五、我卡住的第二次：差点把原来的旺角改坏

落地配好了，接下来让旺角去拉这个 socks5。

我第一反应是去改旺角那个节点，把落地填进去。师傅一句话给我拦下来了：

不新增，你老的旺角节点要直出怎么办？

对啊。旺角本身就是个好用的直出节点，我要是把它改成必走落地，就少了一个直出的选择。

正确做法是新增一个子节点，不是改原节点。

在旺角那台的节点配置里，选「新增子节点」，落地选刚才那个 socks5。这样你会得到两个节点：

  • 旺角 —— 原来的，直出香港
  • 旺角-SG —— 新增的，走 Aether 落地分流

名字一定要区分好，别跟原来的搞混了。

面板里带特殊标记的就是有落地的节点，没标记的就是直出。

最后两步收尾：

套餐里加上新节点

去套餐管理，把新增的这个节点勾上。

更新订阅

客户端拉一下订阅就有了，不用重新导入。

六、验收：怎么确认真的生效了

连上那个 旺角-SG 节点，然后打开：

api64.ipify.org

如果显示的是你 SG 的那个 IPv6，就对了。

（还记得刚才规则里那条 api64.ipify.org 吗？就是为这一步准备的。）

再试试 ChatGPT、Gemini、奈飞，正常的话应该全都是新加坡出口。

我自己验的时候还顺手确认了一下：直连旺角出去是香港 IP，走 旺角-SG 出去就变成 Aether 那台的地址了 —— 两个节点入口完全相同，出口天差地别，这感觉挺奇妙的。

七、几个容易踩的坑

台湾地址是动态的，会变

中华电信家宽来的地址不固定。哪天台湾出口不通了，先回去 ip -6 addr show 看看地址是不是变了，变了就把出站里的 sendThrough 更新一下。

域名策略别选纯 IPv6

选 UseIPv6v4（优先 v6、其次 v4）。有些网站不支持 IPv6，纯 v6 会直接打不开。

香港不需要单独建出站

默认出口就是机器原生的香港 v6，配了反而多余。

新增子节点，别改原节点

改了原节点，你就失去了那条直出线路。多一个节点又不要钱。

地址领下来先 ping 一遍

在 SSH 里 ping6 一下，通了再往面板里填。不然规则配得再漂亮，出口是死的也没用。

写在最后

这套东西的巧妙之处，在于它把两件事拆开了：

中转管「怎么出去」，落地管「从哪儿出去」。

中转机负责抗封锁和低延迟，落地机负责伪装成某个地区的普通家宽用户。两者用 SOCKS5 一对接，就能自由组合 —— 换落地不用动中转，加地区不用动客户端。

而 IPv6 让「一台机器 = 一个地区」这个前提彻底失效了。以前想要四个地区的出口，得买四台机器；现在一台就够，多出来的三个地区是白送的。

师傅那句「一机四吃」，我一开始以为是玩笑。配完才反应过来 —— 这真的是四台机器的效果，而我只付了一台的钱。

最后想说的其实跟技术没什么关系。

整个过程里我问了一堆蠢问题：「socks5 是什么」「这里填 IP 是不是，需要写端口么」「哪个是那里的」「这些方法你是怎么学会的」。师傅一句没嫌烦，图一张张截，命令一段段发，最后还提醒我节点名字要区分好、别把原来的搞坏。

那句「不新增，你老的旺角节点要直出怎么办」，我印象最深 —— 他不只是在教我怎么配，是在教我别把好用的东西弄没了。

折腾这件事，有个人带真的不一样。

感谢师傅 🦆
